# Course Archive: Folder Structure and File Naming Guide

This archive holds teaching and assessment records for EEE courses and service courses, organised by year. This document explains the folder layout, the file naming convention, and how to use both consistently.

---

## 1. Folder Structure

The tree is generated by `create_course_folders.sh`. Top-level layout:

```
.
├── EEE1xxxx/           # First-year EEE courses
├── EEE2xxxx/           # Second-year EEE courses
├── EEE3xxxx/           # Third-year EEE courses
├── EEE4xxxx/           # Fourth-year EEE courses
└── service_courses/    # Courses taught by other departments
    ├── humanities/
    ├── commerce/
    ├── law/
    ├── science/
    ├── health_science/
    ├── mechanical_engineering/
    ├── ched/
    └── other/
```

Each course follows the same nested pattern:

```
EEE2046F/
└── 2024/
    ├── 00_ga_moderation/        # GA courses only (see §1.1)
    ├── 01_administration/
    ├── 02_teaching_materials/
    ├── 03_tutorials/
    ├── 04_practicals/
    ├── 05_assignments/
    ├── 06_projects/
    ├── 07_tests/
    └── 08_exams/
        ├── 01_main/
        └── 02_supp_de/
```

Subfolders are prefixed alphabetically (`a_`, `b_`, `c_` ...) so they sort in a logical order rather than alphabetically by name.

### 1.1 GA Moderation folder

Only present for courses on the GA (Graduate Attribute) list. Holds everything needed for ECSA accreditation evidence. Subfolders:

```
00_ga_moderation/
├── a_dp_tracking/
├── b_assessment_instructions/
├── c_assessment_forms/
├── d_ca_results/
├── e_evidence_sorted_by_students_alphabetically/
└── f_external_moderator_report/
```

GA courses currently on the list: EEE3088F, EEE3096S, EEE3097S, EEE3098S, EEE3099S, EEE3100S, EEE4022F, EEE4022S, EEE4113F, EEE4118F, EEE4119F, EEE4120F, EEE4121F, EEE4124C, EEE4125C, EEE4126F.

### 1.2 Administration subfolders

```
01_administration/
├── a_course_handout/      ← current course handout PDF
├── b_dp_list/             ← DP list (PDF or spreadsheet)
├── c_course_evaluation/   ← end-of-term evaluation form and results
└── d_marksheets/          ← final mark spreadsheets and UCT class list export
```

Drop a UCT PeopleSoft class list export (Emplid/Campus ID column) into `d_marksheets`. The audit tool reads this file to verify GA assessment forms completeness.

### 1.3 Teaching materials subfolders

```
02_teaching_materials/
├── a_prescribed_textbooks/   ← bibliographic references or PDFs of prescribed texts
├── b_notes/                  ← lecture notes
└── c_slides/                 ← lecture slide decks
```

### 1.4 Assessment subfolders

Tutorials, practicals, assignments, and projects all follow the same pattern:

```
03_tutorials/          (or 04_practicals/, 05_assignments/, 06_projects/)
├── a_handouts/        ← instruction sheets
├── b_solutions/       ← memoranda and model answers
└── c_hand-ins/        ← sample student submissions (15 or more per assessment)
```

Tests:

```
07_tests/
├── a_papers/          ← question papers
├── b_solutions/       ← memoranda
└── c_scripts/         ← sample marked scripts (15 or more per test)
```

### 1.5 Exam subfolders

- `01_main` — main exam sitting
- `02_supp_de` — supplementary and deferred exams (combined folder)

Each contains:

```
01_main/
├── a_papers/                      ← question paper
├── b_solutions/                   ← memorandum
├── c_scripts/                     ← scanned student scripts
└── d_external_moderator_reports/  ← moderator reports for paper and scripts
```

## 2. File Naming Convention

### 2.1 Core rules

1. **lower_snake_case** throughout. No spaces, no capitals, no hyphens.
2. **No descriptors** in filenames. The folder path already says what the course, year, and category are, so the filename only carries the type and number.
3. **Two-digit numbering**: `tut_01` not `tut_1`. Sorts correctly past item 9.
4. **Student-submitted files put the student number after the type**: `tut_01_abcxyz001.pdf`.
5. **`memo` suffix** for solutions or memoranda.

### 2.2 Standard abbreviations

| Item | Abbreviation |
|---|---|
| tutorials | `tut` |
| practicals | `prac` |
| assignments | `assign` |
| projects | `proj` |
| tests | `test` |
| exams | `exam` |
| solutions / memorandum | `memo` |
| main (exam) | `main` |
| supplementary | `supp` |
| deferred | `de` |
| slides | `slides_nn` |
| notes | `notes_nn` |

### 2.3 Staff files (handouts, papers, memos)

```
course_handout.pdf
dp_list.pdf
tut_01.pdf
tut_01_memo.pdf
prac_01.pdf
prac_01_memo.pdf
assign_01.pdf
assign_01_memo.pdf
proj_01.pdf
proj_01_memo.pdf
test_01.pdf
test_01_memo.pdf
exam_main.pdf
exam_main_memo.pdf
exam_supp.pdf
exam_supp_memo.pdf
exam_de.pdf
exam_de_memo.pdf
slides_01.pdf
notes_01.pdf
```

### 2.4 Student hand-ins and scripts

Type first, student number after:

```
tut_01_abcxyz001.pdf
prac_01_abcxyz001.pdf
assign_01_abcxyz001.pdf
proj_01_abcxyz001.pdf
test_01_abcxyz001.pdf
exam_main_abcxyz001.pdf
exam_supp_abcxyz001.pdf
exam_de_abcxyz001.pdf
```

This keeps all submissions for a given assessment grouped together when sorted alphabetically.

## 4. Using the Scripts

Two helper scripts ship with this archive:

- **`create_course_folders.sh`** — generates the full empty folder tree for all courses across all years.
- **`flatten_for_export.sh`** — produces long-form filenames (e.g. `eee2046f_2024_exams_main_papers_exam_main.pdf`) for files leaving the archive. Copies originals into an `export/` folder so nothing in the archive is touched.

Both are bash scripts. Running them is straightforward on Linux and macOS, and needs one extra step on Windows.

### 4.1 macOS

The built-in Terminal app runs bash scripts natively.

```bash
cd /path/to/archive
chmod +x create_course_folders.sh flatten_for_export.sh

# Generate the tree (run once)
./create_course_folders.sh

# Export a course-year folder with long-form names
./flatten_for_export.sh -n EEE2xxxx/EEE2046F/2024/   # dry run
./flatten_for_export.sh EEE2xxxx/EEE2046F/2024/      # actual copy
```

If you get `bash: realpath: command not found` on older macOS versions, install coreutils via Homebrew:

```bash
brew install coreutils
```

Then use `grealpath` or symlink it as `realpath`. Most macOS systems from 2018 onwards have it built in.

### 4.2 Linux

Works out of the box on any standard distribution (Ubuntu, Fedora, Debian, etc.).

```bash
cd /path/to/archive
chmod +x create_course_folders.sh flatten_for_export.sh

./create_course_folders.sh
./flatten_for_export.sh -n EEE2xxxx/EEE2046F/2024/
./flatten_for_export.sh EEE2xxxx/EEE2046F/2024/
```

No additional setup needed.

### 4.3 Windows

Bash scripts don't run natively in Command Prompt or PowerShell. You have three options, easiest first.

**Option A: Git Bash (recommended for occasional use)**

If you already have Git for Windows installed, you have Git Bash. Otherwise download it from https://git-scm.com/download/win.

1. Right-click the folder containing the scripts in File Explorer.
2. Choose "Git Bash Here".
3. Run the scripts as on Linux:

```bash
chmod +x create_course_folders.sh flatten_for_export.sh
./create_course_folders.sh
./flatten_for_export.sh -n EEE2xxxx/EEE2046F/2024/
```

**Option B: Windows Subsystem for Linux (recommended for regular use)**

WSL gives you a proper Linux environment inside Windows. One-time setup:

1. Open PowerShell as administrator.
2. Run `wsl --install` and reboot when prompted.
3. Launch "Ubuntu" from the Start menu and create a Linux username and password.

Then access your archive from inside WSL. If the archive lives on `D:\courses`, navigate to it from WSL as:

```bash
cd /mnt/d/courses
chmod +x create_course_folders.sh flatten_for_export.sh
./create_course_folders.sh
./flatten_for_export.sh EEE2xxxx/EEE2046F/2024/
```

**Option C: Run on a colleague's Mac or Linux machine**

If you only ever need to run the scripts occasionally (e.g. once a year when new course folders are created), the simplest path is asking someone in the department who already uses macOS or Linux to run them and share the result.

### 4.4 Common pitfalls (all platforms)

**Line endings.** If the scripts were edited in Notepad or another Windows editor, they may have CRLF line endings that bash chokes on. Symptom: `bad interpreter: /bin/bash^M` or similar. Fix:

```bash
sed -i 's/\r$//' create_course_folders.sh flatten_for_export.sh
```

Or open the file in VS Code, check the bottom-right of the window for "CRLF", and click it to switch to "LF".

**Running in the wrong folder.** `create_course_folders.sh` builds the tree in the *current working directory*, not the folder the script lives in. Always `cd` to where you want the tree to live before running it.

**Spaces in paths.** The scripts handle spaces in filenames, but a folder path like `/Users/me/Course Archive/` can confuse some shells. Quote it when running:

```bash
cd "/Users/me/Course Archive"
```

Or rename the parent folder to use underscores.

**Permission denied.** If `./script.sh` returns "permission denied", you forgot the `chmod +x` step. Either run `chmod +x script.sh` first, or invoke bash directly: `bash script.sh`.

## 5. Auditing the Archive

A companion GUI tool — `course_audit_tool.py` — checks any course-year folder against the expected structure and produces a report. Full documentation is in the tool's own README (`robynverrinder/course-audit-tool`). Key points:

### 5.1 What it checks

- All expected folders are present and non-empty
- Key folders contain the right file types (course handout PDF, DP list spreadsheet, mark sheets with Emplid/Campus ID column, external moderator report)
- Sample hand-in folders contain at least 15 PDF or Word files per assessment group
- GA assessment forms completeness against the reference student count from `d_marksheets`
- No folders are marked NONE but contain files
- No admin status markers (MISSING, UNSIGNED, etc.) remain in folder names
- No duplicate folder names at the same level

### 5.2 Reference student count

Place a UCT PeopleSoft class list export (Emplid/Campus ID column) in `d_marksheets` alongside the marks spreadsheets. Any `.xlsx` or `.csv` with that column is found automatically and used as the reference count for GA and sample hand-in checks.

### 5.3 Running an audit

```bash
conda activate base
python3 course_audit_tool.py
```

Browse to the course-year folder, select the profile (or leave on Auto-detect), set the auditor name and TA, and click **Run Audit and Create Outputs**. The tool saves a `.txt` log and `.xlsx` workbook into the course-year folder.

## 6. Upload Permissions

Not every folder is open to every member of the teaching team. To keep assessment integrity and audit trails clean, uploads are restricted by role.

### 5.1 Roles

- **UG Admin** — the departmental undergraduate administrator. Owns administrative records and student script archiving, moderator correspondence.
- **Convenor** — the course convenor. Owns assessment content (papers, memoranda).
- **Lecturer** — any lecturer teaching on the course (including the convenor).
- **TA** — tutors and teaching assistants assigned to the course.

### 5.2 Permissions Matrix

| Folder | UG Admin | Convenor | Lecturer | TA |
|---|:---:|:---:|:---:|:---:|
| `00_ga_moderation/` (all subfolders) | | ✓ | ✓ | ✓ |
| `01_administration/a_course_handout` | | ✓ | ✓ | ✓ |
| `01_administration/b_dp_list` | ✓ | ✓ | ✓ | ✓ |
| `01_administration/c_course_evaluation` | ✓ | ✓ | ✓ | ✓ |
| `01_administration/d_marksheets` | ✓ | ✓ | ✓ | ✓ |
| `02_teaching_materials/` (all subfolders) | | ✓ | ✓ | ✓ |
| `03_tutorials/` (all subfolders) | | ✓ | ✓ | ✓ |
| `04_practicals/` (all subfolders) | | ✓ | ✓ | ✓ |
| `05_assignments/` (all subfolders) | | ✓ | ✓ | ✓ |
| `06_projects/` (all subfolders) | | ✓ | ✓ | ✓ |
| `07_tests/a_papers` | | ✓ | ✓ | |
| `07_tests/b_solutions` | | ✓ | ✓ | |
| `07_tests/c_scripts` | | ✓ | ✓ | ✓ |

### 5.3 Key restrictions

**Exam papers and memoranda (`08_exams/.../a_papers`, `.../b_solutions`):** only the convenor uploads to these folders, for both main and supplementary/deferred sittings. This protects exam integrity by limiting the number of people with access to live assessment content before the sitting.

**Exam scripts and external moderator reports (`08_exams/.../c_scripts`, `.../d_external_moderator_reports`):** the UG admin and convenor both have upload rights. The UG admin typically archives scripts after marking and handles the moderator correspondence.

**Course handouts (`01_administration/a_course_handout`):** owned by the teaching team, not the UG admin. The convenor is responsible for it being current at the start of each term.

**Everything else in `01_administration`:** shared between the UG admin and the teaching team since DP lists, course evaluations, and marksheets are jointly maintained.

**Test papers and memoranda:** restricted to convenor and lecturers (no TAs), but TAs can upload scripts to `c_scripts` after marking. Tests are lower-stakes than exams, but paper content still needs to be controlled.

**Tutorials, practicals, assignments, projects, teaching materials, GA moderation:** open to the whole teaching team.

### 5.4 Enforcement

These permissions should be reflected in the underlying storage system (SharePoint). This document is the source of truth for what those permissions should be set to. When a course is created or a new staff member joins, set their group memberships to match this matrix.

If you find a permission gap (e.g. you can't upload to a folder you think you should), raise it with the department's IT contact rather than asking someone else to upload on your behalf. Audit trails matter for accreditation.

## 7. FAQs

**Q: Why no descriptors in filenames?**
The folder path already encodes the course, year, and category. Adding a topic descriptor to every filename is repetitive and makes filenames long without adding searchable value. If you need to find a specific topic, use full-text search on the file contents.

**Q: What about files that leave the folder tree, e.g. emailed to a moderator?**
For files going outside the archive, prepend the course code and year manually when you send them, or save a copy with the long form name: `eee2046f_2024_exam_main.pdf`. Inside the archive, keep the short form.

**Q: How do I number multiple papers in the same category, e.g. test 1 and test 2?**
Use the two-digit number: `test_01.pdf`, `test_02.pdf`. Same for tuts, pracs, assignments, projects.

**Q: What if there's only one of something, e.g. one test for the year?**
Still use `test_01.pdf`. Keeps the convention consistent and leaves room to add more later without renaming.

**Q: Where do lecture recordings go?**
Not in this tree. The archive is for written materials, assessments, and evidence. Link to the LMS or video platform from a `links.md` file in `02_teaching_materials` if needed.

**Q: What about source files (Word, LaTeX, PowerPoint) versus PDFs?**
Store the PDF as the canonical version using the convention above. Source files go alongside with the same stem and the native extension: `test_01.tex`, `test_01.docx`. The marker is the extension, not a suffix on the name.

**Q: A student resubmitted, what do I do with the old file?**
Append `_v1`, `_v2` to the older versions: `tut_01_abcxyz001_v1.pdf`. The latest version keeps the clean name.

**Q: What if a course has joint codes, e.g. `EEE2046F_EEE2050F`?**
The folder is already named with both codes joined by underscore. Filenames inside still follow the standard convention; the joint code is implicit from the folder path.

**Q: Where do GA evidence files for individual students go?**
In `00_ga_moderation/e_evidence_sorted_by_students_alphabetically/`, ideally one subfolder per student named with the student number: `abcxyz001/`. Files inside use the standard student hand-in naming.

**Q: Do I need to do anything special for the supp/de folder if there was no supp or deferred exam that year?**
No. Leave the folder empty. The structure is created uniformly for every course-year so future-you doesn't have to recreate it.

**Q: What admin status markers can I append to folder names?**
The audit tool recognises the following markers appended to a folder name. A folder with one of these is flagged as `ADMIN FLAG` for review rather than treated as missing or empty. The marker is stripped when matching the folder against the expected structure, so the folder still counts as being in the right place.

| Marker | Meaning |
|---|---|
| `MISSING` | Content has not yet been added |
| `INCOMPLETE` | Content is partially present |
| `URGENT` | Needs attention before the audit |
| `TODO` | Action still required |
| `UNSIGNED` | Document is present but not yet signed |
| `EMPTY` | Intentionally left empty this year (use NONE instead where possible) |
| `TO BE SIGNED` | Document awaiting signature |

The marker can be separated from the folder name by a space, hyphen, or underscore, in any case: `f. Mark sheets - UNSIGNED`, `f. Mark sheets UNSIGNED`, and `f_mark_sheets_unsigned` are all recognised.

**Q: What is the NONE convention?**
If a folder genuinely has no content for a given year (e.g. no practicals, no projects), append `NONE` to the folder name: `06_projects NONE` or `b. Prescribed texts - NONE`. This signals to the audit tool that the folder is intentionally empty, not accidentally forgotten. Never delete the folder itself — the structure should remain intact.

**Q: What goes in `d_marksheets`?**
Final mark spreadsheets and a UCT PeopleSoft class list export. The class list export (`.xlsx` or `.csv`) must have an `Emplid` or `Campus ID` column. The audit tool reads it to verify GA assessment forms completeness and hand-in counts.

**Q: How should sample hand-ins be organised inside `c_hand-ins` or `c_scripts`?**
Use one subfolder per assessment event. For example, `c_hand-ins/prac_01/`, `c_hand-ins/prac_02/`. Each subfolder needs at least 15 PDF or Word files (the audit tool checks this). A representative spread across the mark range is ideal for accreditation purposes.

**Q: What about the older Legacy (2023/2024) and Current (2025) folder structures?**
Those formats used dot-numbered folders (`01. Administration`, `09. Exam`, etc.) rather than snake_case. They are fully supported by the audit tool using the Legacy and Current profiles respectively. From 2026 onwards, all new course folders use the snake_case New profile structure documented here.

## 8. Quick Reference Card

```
Staff files:    {type}_{nn}[_memo].{ext}
Student files:  {type}_{nn}_{student_number}.{ext}
Exam papers:    exam_{main|supp|de}[_memo].{ext}
Exam scripts:   exam_{main|supp|de}_{student_number}.{ext}
```

All lowercase, snake_case, two-digit numbers, no descriptors.
